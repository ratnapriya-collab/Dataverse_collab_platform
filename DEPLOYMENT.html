1 Architecture at a glance

Three-tier web app. Browser ↔ Next.js (SSR + static + client JS) ↔ FastAPI (REST + JWT) ↔ PostgreSQL. Frontend and backend deploy as two independent services; either can be horizontally scaled behind a load balancer.

5 Database schema

Schema authority: Alembic. Never auto-create tables in production — always migrate.

TablePurposeNotable columns
usersAccountsemail (unique), password_hash (bcrypt), role enum

anchorsFace-anchor records on a partface_uuid, centroid xyz
decisionsEngineering decisionsstate (DRAFT/PROPOSED/ACCEPTED/REJECTED/SUPERSEDED), anchor_id, rationale
threadsv2 comment threadsface_uuid, status, priority, assignee, JSONB tags
repliesMessages in threadsbody, JSONB mentions, JSONB reactions
capturesPersistent 3D viewer screenshotsimage_bytes BYTEA, image_mime, JSONB camera_state, sort_order
eventsAppend-only audit logevery mutation logged for the audit page

Migrations applied through 0006_captures. Run with:

cd backend && alembic upgrade head
Image storage note: Capture screenshots stored as BYTEA in Postgres. Demo-scale (~30 captures × 150 KB JPEG ≈ 4 MB per part) is fine. For 100× scale, swap image_bytes for an object-store key (S3) — public API unchanged.

5432PostgreSQLTCPOnly from app-server security group — never 0.0.0.0/0

Outbound

  • 443 to pypi.org and registry.npmjs.org for dep installs
  • 443 to github.com for git clone / git pull
  • 443 to the DB host if RDS lives in a different VPC subnet

Recommended production fronting

  • AWS ALB (or nginx / Caddy) on :80/:443 with an ACM cert
  • Route /api/* → backend :4000
  • Route everything else → frontend :3010
  • Or split subdomains: app.dataverse.example.com → frontend, api.dataverse.example.com → backend

7 Environment variables

Backend — backend/.env

# Application
APP_NAME=DataVerse Collab API
ENV=production
LOG_LEVEL=INFO

# Database — pick ONE
DATABASE_URL=postgresql+psycopg2://dataverse:STRONG_PASSWORD@db-host:5432/dataverse
# (dev fallback: DATABASE_URL=sqlite:///./dataverse.db)

# JWT — MUST be a long random string in prod;
# MUST be identical across all backend instances if scaled horizontally
JWT_SECRET=replace-with-cryptographically-random-32+-character-string
JWT_ALGORITHM=HS256
JWT_EXPIRES_MINUTES=10080

# CORS — comma-separated list of allowed frontend origins
FRONTEND_ORIGINS=https://app.dataverse.example.com

Frontend — frontend/.env.local

# Public — bundled into the JS sent to browsers.
# Must point at the backend URL the END USER's browser can reach
# (not "localhost" unless the user is on the server).
NEXT_PUBLIC_API_BASE_URL=https://api.dataverse.example.com

Required production secrets

  • JWT_SECRET — generate with openssl rand -base64 64
  • Postgres dataverse user password
  • Postgres postgres superuser password (only used during initial DB setup)

8 Build & run commands

One-time setup (per deploy)

# Clone
git clone https://github.com/ratnapriya-collab/Dataverse_collab_platform.git
cd Dataverse_collab_platform

# Backend
cd dataverse-collab/backend
python -m venv .venv
source .venv/bin/activate                # Linux
# or: .\.venv\Scripts\Activate.ps1       # Windows
pip install -r requirements.txt
# Configure backend/.env (see Section 7)
alembic upgrade head                     # runs DB migrations

# Frontend
cd ../frontend
npm ci                                   # use ci, not install, in production
# Configure frontend/.env.local (see Section 7)
npm run build                            # produces .next/ directory

Run

# Backend — port 4000
cd dataverse-collab/backend
source .venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 4000 --workers 2

# Frontend — port 3010, production mode
cd dataverse-collab/frontend
npm start -- -H 0.0.0.0 -p 3010

Recommended process supervision

OSToolWhy
Linuxsystemd units (one per process)survives reboot, auto-restart, journald logs
Windows ServerNSSM wrapping each commandsurvives reboot AND RDP disconnect
ContainersDocker + docker-compose · ECS / EKSbest for horizontal scale
The repo doesn't ship Dockerfiles or systemd units yet — those should be added during deployment hardening.

9 Security checklist for production

  • JWT_SECRET is cryptographically random, not the default in .env.example
  • DB password is strong and not in git history
  • Postgres :5432 is not reachable from the public internet — only from app servers
  • Frontend served over HTTPS (ACM cert via ALB, or Caddy / Let's Encrypt)
  • FRONTEND_ORIGINS in backend .env lists only your real frontend origin(s), not *
  • Regular DB backups — RDS automated snapshots, or pg_dump on cron
  • CORS allowed origins reviewed
  • Rate limiting in front of /api/* (ALB rules, Cloudflare, or middleware)
  • Server access logs captured to CloudWatch / log aggregation
  • OS patching cadence for the EC2 / VM established
